# DimSpec-LR: Four PDE Families

Runnable fixed-profile configurations for **Coordinate-Specific Factor Design
in Low-Rank Physics-Informed Solvers**.

This release covers the 16 main DimSpec-LR cases in the manuscript:
Helmholtz (H1-H4), anisotropic convection-diffusion-reaction (A1-A4),
stationary space-angle transport (S1-S4), and Klein-Gordon (K1-K4).
It excludes neutron moderation and unpublished transfer experiments, and
does not provide a runner for the complete baseline and ablation matrix.
Shared backend modules retain some general-purpose options; the supported
entry point fixes the final manuscript configurations and does not perform
automatic profile selection.

## Setup

Use Python 3.10 or 3.11 in an isolated environment:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

The executable tests used Python 3.10, PyTorch 2.5.0, NumPy 2.1.2, and
SciPy 1.15.3 on CPU. CUDA is optional. For a CPU-only PyTorch installation:

```bash
python -m pip install torch==2.5.0 --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements.txt
```

## Quick Check

```bash
python run_case.py --list
python prepare_references.py --smoke
python run_case.py --case all --smoke --device cpu --threads 2
python validate_release.py --smoke-results
```

Smoke mode runs two updates with small point sets and separate coarse
references. It checks execution, parameter counts, checkpoint saving, and
evaluation. **It does not reproduce the paper's accuracy.** Smoke outputs
are stored in `smoke_runs/`, never mixed with formal results.

## Run a Final Configuration

H1, A1 and S1-S4 need numerical references for evaluation. These are computed
from the PDE specification, without any external data download:

```bash
python prepare_references.py --cases all
python run_case.py --case H4 --device cpu
python run_case.py --case A3 --device cpu --threads 4
python run_case.py --case S3 --device cuda:0
```

To run the entire suite sequentially:

```bash
python run_case.py --case all --device cuda:0
```

Each default run uses rank 16 and 3,000 optimizer updates. Use `--seed 2026`
or `--seed 3407` for another seed. `--steps` is available for execution checks;
changing it changes the training protocol, including scheduler duration.
Existing run directories are never overwritten. Use a different `--output`
directory to repeat a run.

Outputs are under `runs/<case>/seed_<seed>/`. `invocation.json` records the
resolved configuration and environment; `completed.json` points to the
backend's `summary.json`. Checkpoints and physics histories are retained in
the same run tree. Different backends keep their original output nesting.

## Reproduction Scope

- `configs/*.json` fixes each case's native settings. H2/A2/A3/K2 use cosine
  decay to 0.01 of the initial rate, with rates 0.003/0.001/0.001/0.02.
- H1 uses k0=5 and A1 uses diffusion 0.01. Their references use nested
  257/513 finite-difference grids. Transport references use 2,048 spatial
  cells and 128 angular nodes.
- A3 includes the physics-only 96-by-96 projected initialization and rank-16
  SVD. Float32 solver and reduction differences can change its initialization
  and accuracy across devices or thread counts.
- Checkpoints are selected by physics validation, not reference error.
  Some native runners also log reference errors during training; those values
  do not enter losses or selection. S-case manuscript errors are scalar-flux
  errors, not full angular-field errors.
- `reported_results.csv` contains the manuscript's seed-42 numbers for
  comparison, not new results generated by this release. The 16-case smoke
  check does not constitute a fresh 3,000-update replication of those numbers.
- CPU/CUDA arithmetic, numerical libraries and hardware load affect results
  and timing. Fixed update counts are not equal wall-clock budgets.

## Files and Tests

`src/` contains the required numerical backends. `scripts/train_selected.py`
implements the fixed cosine protocol; the other scripts support curved-field
training and reference generation. `source_manifest.json` records the
backend snapshots and the standalone generic gate dependency. No neutron
solver module is imported, and no source workbook is needed.

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Generated references, model checkpoints, run logs, credentials, and local
environments are excluded from Git. The manuscript PDF and source are not
part of this code release.
